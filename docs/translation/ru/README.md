**Omega-fold** — инструмент с TUI и CLI, который анализирует структуру локального каталога или удалённого сайта (HTTP-обход, ограниченный защитными рамками): полное дерево, статистика по расширениям и семействам файлов, карта ссылок (внутренних и внешних, всех видов), обнаружение битых ссылок. Инструмент набора `omega-`, построенный по принципам Clean Architecture — все технические подробности см. в `docs/ARCHITECTURE.md`.

## 1. Назначение и границы

### Что делает Omega-fold

- Сканирует локальный каталог (настоящий `os.walk`) или обходит удалённый сайт в ширину (BFS) в строгих защитных рамках.
- Строит полное дерево (файлы и каталоги, глубина, размер) и распределяет его по семействам (`images`/`documents`/`code`/`data`/`archives`/`fonts`/`video`/`audio`/`text`/`other`) — см. [§4](#4-семейства-файлов).
- Извлекает все ссылки (`<a href>`, `<img src>`, `<script src>`, `<link href>`, `<form action>`) из каждой HTML-страницы или файла, классифицирует их (внутренние абсолютные/относительные, внешние, якоря, `mailto:`/`tel:`/`javascript:`/`data:`) и проверяет их существование — см. [§5](#5-ссылки-и-проверка).
- Считает статистику: распределение по расширениям и семействам, самые большие файлы, файлы с наибольшим числом исходящих ссылок, чаще всего упоминаемые внешние домены.
- Показывает результат в TUI (Textual) или в CLI для сценариев, с тремя видами экспорта (JSON, текст, HTML с 5 темами).
- Хранит постоянную историю сканирований (SQLite), которую можно просматривать и запускать повторно.

### Чего Omega-fold не делает

- Анализ содержимого или SEO (заголовки, мета-описания, плотность ключевых слов).
- Обход без защитных рамок — глубина, число страниц и пауза между запросами всегда действуют.
- Отрисовку JavaScript на стороне клиента (страница забирается в том виде, в каком её отдаёт сервер, и не выполняется в безголовом браузере).
- Активное сканирование уязвимостей, фаззинг, перебор.
- Веб-панель.

## 2. Установка

### Требования

- Python 3.10+
- Подключение к Интернету, для зависимостей
- Для TUI: шрифт [Nerd Font](https://www.nerdfonts.com/), установленный в терминале, для значка в заголовке — без него этот символ отображается пустым квадратом (то же ограничение, что у эмодзи, но такие шрифты у пользователей терминала встречаются гораздо чаще). Его отсутствие не влияет на работу — это чисто внешний вид.

### Установка

```bash
[ -d omega-fold ] && echo "ℹ️ Уже распаковано здесь, шаг пропущен." || tar -xzf omega-fold.tar.gz
cd omega-fold/
chmod +x install.sh
./install.sh
```

`install.sh`:

1. Создаёт виртуальное окружение `.venv`, если его ещё нет.
2. Устанавливает зависимости (`vendor/omega-lib/`, затем `pip install -e .`; `pyproject.toml` остаётся единственным источником истины).
3. Делает `omega-fold.sh` и `install.sh` исполняемыми.
4. Добавляет псевдоним `fold` в `~/.bashrc` и `~/.zshrc` (без дублирования, если он уже есть).

### Зависимости

Объявлены в `pyproject.toml` (без `requirements.txt`):
- `omega-lib`: общая библиотека набора (темы экспорта, `ConfidenceLevel`) — поставляется в `vendor/omega-lib/`
- `httpx`: синхронная проверка внешних ссылок (`LinkChecker`)
- `aiohttp`: асинхронный HTTP-обход (`DistantCrawler`)
- `beautifulsoup4` + `lxml`: извлечение HTML-ссылок
- `jinja2`: шаблоны для экспорта в HTML
- Зависимости для разработки (`pip install -e ".[dev]"`): `pytest`, `pytest-asyncio`, `pytest-cov`, `pytest-httpserver`, `ruff`, `mypy`, `import-linter`

## 3. Использование

### Интерактивный режим (TUI)

Рекомендуется для повседневной работы — запускается без аргументов:

```bash
./omega-fold.sh
```
если вы создали псевдоним, просто наберите `fold` в терминале:
```bash
fold
```

Порядок работы: заставка (закрывается нажатием клавиши или щелчком) → главное меню (Сканировать / История / Настройки / Справка) → ввод цели, типа (локальный/удалённый), режима (статический/динамический) и защитных рамок удалённого обхода, у каждого поля своя понятная подпись → сканирование (неопределённый индикатор, журнал операций в реальном времени, кнопка Отмена в любой момент) → подробности сканирования (распределение по семействам и расширениям, дерево, битые ссылки, экспорт) → история (просмотр подробностей, **прямой экспорт** без перехода к подробностям, повторный запуск) и настройки из главного меню. Подстройка под терминал (цвета, размер, упрощение структуры) происходит автоматически.

#### Сочетания клавиш

| Клавиша | Действие |
|---|---|
| `↑` / `↓` | Переход между элементами экрана |
| `Tab` / `Shift+Tab` | Переход между полями формы |
| `Esc` | Возврат на предыдущий экран (подтверждение выхода на главном экране) |
| `t` | Следующая тема (применяется сразу, без подтверждения) |
| `r` | Обновить определение терминала |
| `a` | Показать справку |
| `q` | Выйти (с подтверждением) |

### Языки интерфейса

Интерфейс доступен на 17 языках: французском, английском, испанском, португальском (Бразилия), итальянском, немецком, нидерландском, польском, русском, упрощённом китайском, вьетнамском, тайском, индонезийском, японском, корейском, хинди и арабском. Язык выбирается в Настройках («Langue / Language») и применяется после перезапуска интерфейса; переменная `OMEGA_FOLD_LANG` (например, `OMEGA_FOLD_LANG=ru ./omega-fold.sh`) задаёт язык на один сеанс. При запуске из omega-suite omega-fold использует язык набора. В текстовой консоли Linux (TTY) языки с нелатинской письменностью на время сеанса показываются по-английски. Командная строка остаётся на французском.

### Контакты и поддержка

Справка (клавиша `a`) предлагает экран **Контакты и поддержка**: *Угостить кофе* (страница PayPal разработчика), *Связаться с поддержкой* (адрес электронной почты и контактная форма сайта, показанные открыто), *Зарегистрироваться как пользователь (анонимно)* и *Проверить обновления*. Регистрация добровольная, по умолчанию отключена и отправляется только один раз: она служит лишь для подсчёта пользователей и, по желанию, их континента или страны (закрытые списки, никогда не свободный текст). Отправляются случайно сгенерированный ключ, название программы (`omega-fold`) и её версия; никогда имя, имя машины, настройка, цель или результат. IP-адрес не сохраняется в регистрациях, но, как при любом посещении, проходит через проверки безопасности и журнал принимающего сервера. Отозвать регистрацию можно в любой момент на том же экране (*Больше не регистрировать меня*). Проверка обновлений лишь читает список версий, опубликованных на сайте, и никогда без щелчка.

### Режим для сценариев (CLI)

Любая подкоманда включает режим CLI:

```bash
# Локальное сканирование (дерево + внутренние ссылки)
./omega-fold.sh scan /var/www/moysait --type local

# Локальное сканирование в динамическом режиме (проверяет и внешние ссылки по HTTP)
./omega-fold.sh scan /var/www/moysait --type local --mode dynamic

# Удалённое сканирование (обход BFS от начального URL)
./omega-fold.sh scan https://example.org --type distant --mode dynamic \
    --max-depth 3 --max-pages 200 --delay 200 --respect-robots

# История (с фильтром по цели)
./omega-fold.sh history --target /var/www/moysait --limit 20

# Подробности сканирования (текст, JSON или HTML) — на выбор 5 тем экспорта
./omega-fold.sh show <scan_id> --format html --theme omega-base --output otchet.html
```

Параметры `scan`:

| Параметр | По умолчанию | Действие |
|---|---|---|
| `--type` | *(обязателен)* | `local` или `distant` (удалённый) |
| `--mode` | `static` | `static` (внешние ссылки не проверяются) или `dynamic` (проверяются по HTTP) |
| `--max-depth` | `5` | Максимальная глубина обхода (удалённое сканирование) |
| `--max-pages` | `1000` | Максимальное число обходимых страниц (удалённое сканирование) |
| `--delay` | `100` | Пауза (мс) между двумя запросами (удалённое сканирование) |
| `--user-agent` | `omega-fold/0.1` | Отправляемый заголовок `User-Agent` (удалённое сканирование) |
| `--respect-robots` | выключено | Соблюдает `robots.txt` (удалённое сканирование) |

При удалённом сканировании цель без схемы (`example.org`) автоматически дополняется до `https://example.org` — указывать схему нужно, только чтобы явно задать `http://`.

Если на сайте больше страниц, чем `--max-pages` (по умолчанию 1000), сканирование останавливается на пределе, но явно сообщает об этом: `scan.status` принимает значение `completed_truncated` вместо `completed`, с заметным предупреждением в сводке CLI, на экране подробностей TUI и в экспорте HTML — указанное число файлов тогда не отражает настоящий размер сайта; для полного охвата запустите снова с бо́льшим `--max-pages`.

Если псевдоним создан `install.sh`, `fold scan ...` работает из любого места терминала, без префикса `./omega-fold.sh`.

## 5. Ссылки и проверка

### Классификация

Каждая найденная ссылка (`href`/`src`/`action`) классифицируется в таком порядке приоритета:

| Тип | Когда распознаётся | Пример |
|---|---|---|
| `empty` | Пустая строка | `href=""` |
| `mailto` / `tel` / `javascript` / `data` | Особая схема | `mailto:x@y.z` |
| `anchor` | Начинается сразу с `#` (чистый якорь) | `#section` |
| `external` | `http://`, `https://` или `//` (относительно протокола) | `https://example.org` |
| `absolute` | Начинается с `/` | `/img/logo.png` |
| `relative` | Всё остальное | `img/logo.png`, `../page.html` |

`absolute` и `relative` — две формы **внутренней** ссылки: ссылка `page.html#section` остаётся `relative` (фрагмент в конце не делает её простым якорем — она действительно ведёт к другому ресурсу).

### Проверка

- **Внутренняя ссылка**: всегда проверяется по множеству путей, действительно найденных при сканировании (без сетевых запросов) — `absolute` разрешается от корня сканирования, `relative` с разделителем — от каталога исходного файла, `relative` без разделителя (только имя файла) ищется по всему дереву. При удалённом сканировании проверка выполняется вторым проходом после окончания обхода, по множеству страниц, действительно успешно посещённых, — страница за защитными рамками или заблокированная `robots.txt` остаётся `unchecked` и никогда не считается `broken` по догадке.
- **Внешняя ссылка**: проверяется HTTP-запросом (HEAD, затем GET, если HEAD не удался) только в режиме `dynamic` — в режиме `static` она остаётся `unchecked`.

## 6. Защитные рамки удалённого обхода

Всегда включены и никогда не отключаются — настраиваются только их пороги:

- **Глубина** (`--max-depth`): ограничивает только постановку новых страниц в очередь обхода; ссылки, найденные на уже посещённой странице, всегда попадают в результат, даже если страница, на которую они ведут, не будет посещена.
- **Число страниц** (`--max-pages`): ограничивает общее число посещённых страниц на всех глубинах.
- **Пауза** (`--delay`): перерыв между двумя последовательными HTTP-запросами.
- **Тот же домен**: посещаются только внутренние ссылки на тот же `netloc`, что и у начального URL, — это проверяется и по пути ссылки, и по URL, **фактически загруженному после перенаправления**: постоянная ссылка, путь которой похож на внутренний каталог (`/go/xyz`, `/public/imya/`), но которая на деле перенаправляет на внешний домен, никогда не считается страницей сканируемого сайта (её содержимое было бы не вашим).
- **`robots.txt`** (`--respect-robots`): усиливает защитные рамки, а не ослабляет их — запрещённая страница никогда не посещается, её исходящие ссылки остаются `unchecked`.

## 7. Архитектура

Omega-fold построен по принципам **Clean Architecture** (domain / application / infrastructure / interfaces / ports / core / app / plugins / shared), согласованным с шаблоном набора `omega-` (см. `omega-scan`/`omega-check`/`omega-deep`), и проверяется `import-linter` при каждом изменении. Все подробности — в **`docs/ARCHITECTURE.md`**.

Очень краткий обзор:

```text
src/omega_fold/
├── domain/          Чистая предметная логика: сканирования, дерево (tree), ссылки, статистика, отчёты
├── application/     Сценарии использования (commands/queries) — run_scan (локальный/удалённый), export_scan_report...
├── ports/           Контракты, ожидаемые приложением (local_fs_reader, distant_crawler,
│                    html_link_extractor, link_checker, scan_repository, report_exporter...)
├── infrastructure/  Конкретные реализации (os.walk, aiohttp, httpx, BeautifulSoup, SQLite,
│                    экспортёры Jinja2 — Textual здесь НЕТ)
├── interfaces/      tui/ (Textual) и cli/ (для сценариев), со строгим равенством возможностей
├── app/             Сборка (DependencyContainer, bootstrap, жизненный цикл)
├── core/, shared/   Общий словарь, вспомогательные средства вне предметной логики
└── plugins/         Структура заложена, пуста (ни одно направление расширения не подтверждено)
```

Правила проектирования:
- `domain/tree/service.py`: собирает уже известный плоский список файлов в дерево и никогда не выполняет ввод-вывод — настоящий обход (`os.walk`) находится в `infrastructure/filesystem/`.
- `domain/scans/policies.py`: защитные рамки обхода (глубина/страницы/домен), чистая логика, проверяемая без сети.
- `infrastructure/filesystem/` и `infrastructure/network/`: выполняют ввод-вывод (диск, HTTP) и никогда не выносят оценок.
- `infrastructure/exporters/`: читают уже собранный результат сканирования и никогда не пересчитывают статистику.
- `infrastructure/storage/sqlite/`: хранит только исходные данные (`scans`/`files`/`links`) — дерево и статистика пересчитываются при чтении теми же чистыми функциями, что и при первом сканировании (см. `DECISIONS_ARCHITECTURE.md`, D-011), и никогда не дублируются в базе.

## 8. Экспорт

Текстовые и HTML-отчёты пишутся на языке, выбранном в Настройках («Язык экспорта», по умолчанию — язык интерфейса); JSON остаётся данными и не переводится. По умолчанию отчёты создаются в `var/exports/` (рабочий путь привязан к папке проекта, `$OMEGA_FOLD_VAR_DIR` позволяет его переопределить) или по указанному пути (`--output`).

### JSON — источник истины

Полная структура результата (`Scan` + дерево + ссылки + статистика), строго сериализуемая в JSON.

### Текст — компактный отчёт для чтения

Сводка, распределение по семействам, дерево ASCII (не глубже 6 уровней — текстовый отчёт не предназначен для перечисления дерева из тысяч файлов), список битых ссылок.

### HTML — самостоятельный веб-отчёт

5 тем на выбор (`--theme`). Общий размер сайта выводится первым (это главная цель отчёта о сканировании) и везде — в CLI, TUI, экспорте — показывается в удобном виде (КБ/МБ/ГБ...), а не в сырых байтах. Собственная вёрстка: контейнер, сетка статистики, SVG-гистограмма распределения по семействам (нарисована вручную, без тяжёлой библиотеки графиков — та же техника, что и у диаграммы архитектуры в `omega-deep`), таблицы расширений и самых больших файлов. Из внешних доменов первые 20 показаны сразу, остальные — в сворачиваемой панели (полезно для сайта с сотнями внешних перенаправлений); список битых ссылок по умолчанию свёрнут.

Дерево выводится как родной **многоуровневый** HTML: один `<details>` на каталог, по умолчанию открыт только корень, каждая вложенная папка раскрывается независимо по щелчку (по мотивам сценария пользователя для создания индексов) — браузер раскладывает только открытое содержимое, поэтому отчёт остаётся удобным даже для сайта из десятков тысяч файлов, без JavaScript.

## 9. История

Каждое сканирование сохраняется (SQLite, `var/db/omega-fold.db`). Историю можно просматривать по цели (`omega-fold history --target ...`), смотреть подробности прошлого сканирования (`omega-fold show <scan_id>`) или пользоваться меню История в TUI (включая повторный запуск).

## 10. Совместимость с терминалами

TUI (Textual) автоматически определяет возможности терминала (эмулятор, размер) и соответственно подстраивает свою структурную таблицу стилей (`complete`/`standard`/`reduced`/`mono`), без ручных параметров. Режим CLI всегда остаётся простым текстом, независимо от терминала. Это правило общее для всего набора `omega-` (`omega-lib`, `terminal/policies.py`).

### Профиль по определённому эмулятору

| Эмулятор | Начальный профиль |
|---|---|
| Ghostty, Alacritty, WezTerm, Kitty | `complete` |
| Konsole, GNOME Terminal, Terminator, Xfce4 Terminal | `standard` |
| xterm, urxvt, современный SSH | `reduced` |
| TTY Linux, старый SSH | `mono` |
| Нераспознанный эмулятор | `reduced` (запасной вариант по умолчанию) |

### Профиль по размеру терминала

| Минимальный размер (столбцы × строки) | Верхний предел профиля |
|---|---|
| 120 × 32 | `complete` |
| 100 × 28 | `standard` |
| 80 × 24 | `reduced` |
| меньше | `mono` |

Итоговый профиль — **более строгий из двух** (эмулятор и размер); его можно обновить на лету клавишей `r`.
