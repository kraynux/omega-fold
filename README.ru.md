**Omega-fold** — инструмент с TUI + CLI для анализа структуры локального каталога или удалённого сайта (HTTP-обход с защитными ограничениями): полное дерево, статистика по расширениям/семействам файлов, карта ссылок (внутренних/внешних, всех типов), обнаружение битых ссылок. Пятый инструмент набора `omega-` (после `omega-scan`, `omega-stress`, `omega-check` и `omega-deep`), построенный по принципам Clean Architecture. Полные технические сведения приведены в `docs/ARCHITECTURE.md`.

## 1. Назначение и область

### Что делает Omega-fold

- Сканирует локальный каталог (реальный `os.walk`) или выполняет BFS-обход удалённого сайта, ограниченный строгими защитными мерами.
- Строит полное дерево (файлы/каталоги, глубина, размер) и классифицирует его по семействам (`images`/`documents`/`code`/`data`/`archives`/`fonts`/`video`/`audio`/`text`/`other`) — см. [§4](#4-семейства-файлов).
- Извлекает все ссылки (`<a href>`, `<img src>`, `<script src>`, `<link href>`, `<form action>`) из каждой HTML-страницы/файла, классифицирует их (внутренние абсолютные/относительные, внешние, якоря, `mailto:`/`tel:`/`javascript:`/`data:`) и проверяет их существование — см. [§5](#5-ссылки-и-проверка).
- Вычисляет статистику: распределение по расширениям/семействам, самые большие файлы, файлы с наибольшим числом исходящих ссылок, внешние домены с наибольшим количеством ссылок.
- Представляет результаты в TUI (Textual) или через скриптуемый CLI, с тремя форматами экспорта (JSON, текст, HTML с 5 темами).
- Хранит постоянную историю сканирований (SQLite), доступную для просмотра и повторного запуска.

### Чего Omega-fold не делает

- Анализ контента или SEO (заголовки, мета-описания, плотность ключевых слов).
- Обход без защитных мер: глубина, число страниц и задержка между запросами всегда активны.
- Клиентский рендеринг JavaScript (страница загружается в том виде, в котором отдана сервером, но не выполняется в headless-браузере).
- Активное сканирование уязвимостей, фаззинг или brute force.
- Веб-панель управления.

## 2. Установка

### Требования

- Python 3.10+
- Подключение к Интернету для установки зависимостей
- Для TUI: установленный в терминале [Nerd Font](https://www.nerdfonts.com/) для значка заголовка. Без него символ отображается пустым квадратом (такое же ограничение, как у emoji, хотя Nerd Font гораздо шире доступен пользователям терминала). Отсутствие шрифта не влияет на работу и имеет только косметическое значение.

### Установка

```bash
[ -d omega-fold ] && echo "ℹ️ Уже распаковано здесь, шаг пропущен." || tar -xzf omega-fold.tar.gz
cd omega-fold/
chmod +x install.sh
./install.sh
```

`install.sh`:

1. Создаёт виртуальное окружение `.venv`, если оно ещё не существует.
2. Устанавливает зависимости (`vendor/omega-lib/`, затем `pip install -e .`; `pyproject.toml` остаётся единственным источником истины).
3. Делает `omega-fold.sh` и `install.sh` исполняемыми.
4. Добавляет alias `fold` в `~/.bashrc` и `~/.zshrc` (без дублирования, если он уже существует).

### Зависимости

Указаны в `pyproject.toml` (`requirements.txt` отсутствует):
- `omega-lib`: общая библиотека набора (темы экспорта, `ConfidenceLevel`) — включена в `vendor/omega-lib/`
- `httpx`: синхронная проверка внешних ссылок (`LinkChecker`)
- `aiohttp`: асинхронный HTTP-обход (`DistantCrawler`)
- `beautifulsoup4` + `lxml`: извлечение HTML-ссылок
- `jinja2`: шаблонизация HTML-экспорта
- Зависимости разработки (`pip install -e ".[dev]"`): `pytest`, `pytest-asyncio`, `pytest-cov`, `pytest-httpserver`, `ruff`, `mypy`, `import-linter`

## 3. Использование

### Интерактивный режим (TUI)

Рекомендуется для ежедневного использования — запускается без аргументов:

```bash
./omega-fold.sh
```
Если alias создан, просто введите в терминале:
```bash
fold
```

Сценарий: стартовый экран (закрывается после нажатия клавиши или щелчка) → главное меню (Scanner / History / Settings / Help) → ввод цели, типа (локальный/удалённый), режима (статический/динамический) и защитных ограничений удалённого обхода, каждое поле имеет понятную подпись → сканирование (индикатор неопределённого прогресса, журнал операций в реальном времени, кнопка Отмена доступна в любой момент) → подробности сканирования (распределение по семействам и расширениям, дерево, битые ссылки, экспорт) → история (просмотр подробностей, **прямой экспорт** без перехода через экран подробностей, повторный запуск) и настройки из главного меню. Адаптация к терминалу (цвета, размер, структурное упрощение) выполняется автоматически.

#### Сочетания клавиш

| Клавиша | Действие |
|---|---|
| `↑` / `↓` | Переход между элементами экрана |
| `Tab` / `Shift+Tab` | Переход между полями формы |
| `Esc` | Возврат на предыдущий экран (на главном экране запрашивается подтверждение выхода) |
| `t` | Следующая тема (применяется сразу, без подтверждения) |
| `r` | Обновить обнаружение терминала |
| `a` | Показать справку |
| `q` | Выйти (с подтверждением) |

### Скриптуемый режим (CLI)

Любая подкоманда запускает режим CLI:

```bash
# Локальное сканирование (дерево + внутренние ссылки)
./omega-fold.sh scan /var/www/monsite --type local

# Локальное сканирование в динамическом режиме (также проверяет внешние ссылки по HTTP)
./omega-fold.sh scan /var/www/monsite --type local --mode dynamic

# Удалённое сканирование (BFS-обход от начального URL)
./omega-fold.sh scan https://example.org --type distant --mode dynamic \
    --max-depth 3 --max-pages 200 --delay 200 --respect-robots

# История (с фильтрацией по цели)
./omega-fold.sh history --target /var/www/monsite --limit 20

# Подробности сканирования (текст, JSON или HTML) — доступны 5 тем экспорта
./omega-fold.sh show <scan_id> --format html --theme omega-base --output rapport.html
```

Параметры `scan`:

| Параметр | По умолчанию | Действие |
|---|---|---|
| `--type` | *(обязательно)* | `local` или `distant` |
| `--mode` | `static` | `static` (внешние ссылки не проверяются) или `dynamic` (проверяются по HTTP) |
| `--max-depth` | `5` | Максимальная отслеживаемая глубина (удалённое сканирование) |
| `--max-pages` | `1000` | Максимальное число обойдённых страниц (удалённое сканирование) |
| `--delay` | `100` | Задержка (мс) между двумя запросами (удалённое сканирование) |
| `--user-agent` | `omega-fold/0.1` | Отправляемый заголовок `User-Agent` (удалённое сканирование) |
| `--respect-robots` | отключён | Соблюдает `robots.txt` (удалённое сканирование) |

Для удалённого сканирования цель без схемы (`example.org`) автоматически дополняется до `https://example.org`; указывать её не требуется, кроме случая, когда нужно явно принудительно использовать `http://`.

Если у сайта больше страниц, чем задано в `--max-pages` (по умолчанию 1000), сканирование останавливается на лимите, но явно сообщает об этом: `scan.status` получает значение `completed_truncated` вместо `completed`, а предупреждение отображается в сводке CLI, на экране подробностей TUI и в HTML-экспорте. В этом случае указанное число файлов не является фактическим размером сайта; для полного охвата повторите запуск с более высоким `--max-pages`.

Если alias создан через `install.sh`, команда `fold scan ...` работает из любого места в терминале без префикса `./omega-fold.sh`.

## 5. Ссылки и проверка

### Классификация

Каждая найденная ссылка (`href`/`src`/`action`) классифицируется в следующем порядке приоритета:

| Тип | Распознаётся, когда | Пример |
|---|---|---|
| `empty` | Пустая строка | `href=""` |
| `mailto` / `tel` / `javascript` / `data` | Специальная схема | `mailto:x@y.z` |
| `anchor` | Начинается непосредственно с `#` (чистый якорь) | `#section` |
| `external` | `http://`, `https://` или `//` (protocol-relative) | `https://example.org` |
| `absolute` | Начинается с `/` | `/img/logo.png` |
| `relative` | Всё остальное | `img/logo.png`, `../page.html` |

`absolute` и `relative` — две формы **внутренней** ссылки. Ссылка `page.html#section` остаётся `relative`: конечный фрагмент не делает её простой якорной ссылкой, она всё равно ведёт к другому ресурсу.

### Проверка

- **Внутренняя ссылка**: всегда проверяется по набору путей, реально найденных во время сканирования (без сетевого запроса). `absolute` разрешается относительно корня сканирования; `relative` с разделителем — относительно каталога исходного файла; `relative` без разделителя (только имя файла) ищется по всему дереву. При удалённом сканировании проверка выполняется вторым проходом после завершения обхода по набору страниц, успешно посещённых на самом деле. Страница вне защитных ограничений или заблокированная `robots.txt` остаётся `unchecked`, а не предполагается `broken`.
- **Внешняя ссылка**: проверяется HTTP-запросом (HEAD, затем GET, если HEAD завершился ошибкой) только в режиме `dynamic`; в режиме `static` она остаётся `unchecked`.

## 6. Защитные ограничения удалённого обхода

Всегда активны и не могут быть отключены; настраиваются только их пороговые значения:

- **Глубина** (`--max-depth`): ограничивает только постановку новых страниц в очередь обхода; ссылки, найденные на уже посещённой странице, всегда включаются в результат, даже если целевая страница не будет обработана.
- **Количество страниц** (`--max-pages`): ограничивает общее число посещённых страниц на всех уровнях глубины.
- **Задержка** (`--delay`): пауза между двумя последовательными HTTP-запросами.
- **Тот же домен**: обрабатываются только внутренние ссылки на тот же `netloc`, что и у начального URL. Проверяется как путь ссылки, так и URL, **фактически загруженный после перенаправления**: permalink, путь которого выглядит как внутренний каталог (`/go/xyz`, `/public/nom/`), но который на деле перенаправляет на внешний домен, никогда не считается страницей сканируемого сайта.
- **`robots.txt`** (`--respect-robots`): усиливает защитные ограничения, а не ослабляет их; запрещённая страница никогда не посещается, а её исходящие ссылки остаются `unchecked`.

## 7. Архитектура

Omega-fold построен по **Clean Architecture** (domain / application / infrastructure / interfaces / ports / core / app / plugins / shared), соответствует шаблону набора `omega-` (см. `omega-scan`/`omega-check`/`omega-deep`) и проверяется с помощью `import-linter` после каждого изменения. Полное описание находится в **`docs/ARCHITECTURE.md`**.

Краткий обзор:

```text
src/omega_fold/
├── domain/          Чистая бизнес-логика: сканирования, дерево, ссылки, статистика, отчёты
├── application/     Сценарии использования (commands/queries) — run_scan (local/distant), export_scan_report...
├── ports/           Контракты приложения (local_fs_reader, distant_crawler,
│                    html_link_extractor, link_checker, scan_repository, report_exporter...)
├── infrastructure/  Конкретные реализации (os.walk, aiohttp, httpx, BeautifulSoup, SQLite,
│                    экспортёры Jinja2 — Textual находится НЕ здесь)
├── interfaces/      tui/ (Textual) и cli/ (скриптуемый), со строгим функциональным соответствием
├── app/             Сборка (DependencyContainer, bootstrap, жизненный цикл)
├── core/, shared/   Общая терминология, утилиты, не относящиеся к бизнес-логике
└── plugins/         Подготовленная пустая структура (нет подтверждённой оси расширения)
```

Правила проектирования:
- `domain/tree/service.py`: преобразует уже известный плоский список файлов в дерево и никогда не выполняет I/O; реальный обход (`os.walk`) находится в `infrastructure/filesystem/`.
- `domain/scans/policies.py`: защитные ограничения обхода (глубина/страницы/домен), чистая логика, тестируемая без сети.
- `infrastructure/filesystem/` и `infrastructure/network/`: выполняют I/O (диск, HTTP), но никогда не принимают решений.
- `infrastructure/exporters/`: читают уже собранный результат сканирования и никогда не пересчитывают статистику.
- `infrastructure/storage/sqlite/`: хранит только исходные данные (`scans`/`files`/`links`); дерево и статистика пересчитываются при чтении теми же чистыми функциями, что и при первоначальном сканировании (см. `DECISIONS_ARCHITECTURE.md`, D-011), и никогда не дублируются в базе данных.

## 8. Экспорт

По умолчанию отчёты создаются в `var/exports/` (runtime-путь привязан к каталогу проекта; для переопределения используется `$OMEGA_FOLD_VAR_DIR`) либо по пути, указанному через `--output`.

### JSON, источник истины

Полная структура результата (`Scan` + дерево + ссылки + статистика), строго сериализуемая в JSON.

### Текст, компактный отчёт для чтения

Сводка, распределение по семействам, ASCII-дерево (ограничено 6 уровнями глубины: текстовый отчёт не предназначен для перечисления дерева из тысяч файлов) и список битых ссылок.

### HTML, автономный веб-отчёт

Доступно 5 тем (`--theme`). Общий размер сайта выводится первым (это главная цель отчёта сканирования) и везде отображается в читаемом формате (KB/MB/GB...) — CLI, TUI и экспорт — вместо необработанных байтов. Используется отдельная разметка: контейнер, сетка статистики, SVG-гистограмма распределения по семействам (нарисована вручную, без тяжёлой зависимости для графиков; та же техника, что в архитектурной диаграмме `omega-deep`), таблицы расширений/самых больших файлов. Для связанных внешних доменов напрямую показываются первые 20, остальные находятся в сворачиваемой панели; список битых ссылок по умолчанию свёрнут.

Дерево отображается в нативном **многоуровневом** HTML: один `<details>` на каталог, по умолчанию открыт только корень, каждый подкаталог раскрывается независимо по щелчку — без JavaScript.

## 9. История

Каждое сканирование сохраняется (SQLite, `var/db/omega-fold.db`). Историю можно просматривать по цели (`omega-fold history --target ...`), открыть сведения о прошлом сканировании (`omega-fold show <scan_id>`) или использовать меню History в TUI (включая повторный запуск).

## 10. Совместимость с терминалами

TUI (Textual) автоматически определяет возможности терминала (эмулятор и размер) и соответствующим образом адаптирует структурную таблицу стилей (`complete`/`standard`/`reduced`/`mono`) без ручного флага. Режим CLI всегда остаётся обычным текстом и не зависит от терминала. Политика общая для всего набора `omega-` (`omega-lib`, `terminal/policies.py`).

### Профиль по обнаруженному эмулятору

| Эмулятор | Начальный профиль |
|---|---|
| Ghostty, Alacritty, WezTerm, Kitty | `complete` |
| Konsole, GNOME Terminal, Terminator, Xfce4 Terminal | `standard` |
| xterm, urxvt, современный SSH | `reduced` |
| Linux TTY, устаревший SSH | `mono` |
| Неизвестный эмулятор | `reduced` (резервный профиль по умолчанию) |

### Профиль по размеру терминала

| Минимальный размер (столбцы × строки) | Верхняя граница профиля |
|---|---|
| 120 × 32 | `complete` |
| 100 × 28 | `standard` |
| 80 × 24 | `reduced` |
| меньше | `mono` |

Итоговый профиль — **наиболее ограничительный из двух** (эмулятора и размера); его можно обновить в реальном времени клавишей `r`.

Структура: `tests/unit/` (domain и infrastructure без реального I/O: экспортёры, SVG-график и разметка стартового экрана TUI), `tests/integration/` (реальная файловая система через `tmp_path`, фиктивный HTTP-сервер `pytest-httpserver`, настоящая база SQLite, CLI от начала до конца), `tests/tui/` (навигация через `Pilot`, структурные проверки; автоматическая визуальная проверка не заявляется, см. `docs/ARCHITECTURE.md` §TUI Interface).
